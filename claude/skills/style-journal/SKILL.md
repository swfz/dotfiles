# style-journal

社内エンジニア向けの**技術ジャーナル風エディトリアルスタイル** (ライト基調・ダーク自動対応) で、
提案・状況報告用の縦スクロール HTML 資料を、外部リソース非依存の単一 HTML として生成する (JS はテーマ切替ボタンのみ)。
style-terminal の姉妹スキル。あちらが「見せる (プレゼン)」用、こちらが「判断してもらう (提案・報告)」用。

## このスキルの前提思想 (資料の書き方に踏み込む)

見た目より先に**構造**を守る。テンプレートはこの構造を強制するようにできている:

1. **結論ファースト**: マストヘッド直下の `.summary` に「何を依頼したいか / 今どういう状態か」を必ず書く。期限つきの依頼はここで太字にする
2. **見出しはキーメッセージ**: 「背景」ではなく「スキャン費用が3ヶ月で2倍になっている」。見出しだけ読めば流れがわかるように
3. **事実・解釈・依頼を区別**: `.lab-chip` (事実=無彩枠 / 解釈=アクセント枠 / 依頼=アクセント地) で書き手の3区分を視覚化する
4. **提案は 課題 → 選択肢 → 推奨と根拠 → 依頼**、**報告は ステータス → 前回からの差分 → リスク → 次のアクション** の骨格
5. **アクションには必ず担当と期限** (`.tbl` のアクションテーブル)。報告の本体は**差分** (`.diff`)
6. **メタ情報を必ず載せる**: 日付・宛先・作成者・ステータス (マストヘッド) と 次回報告・更新履歴 (奥付)

## デザインの要点

| 要素 | 仕様 |
|------|------|
| 紙面 | カード (枠・影) は使わず**フラット**。`--sheet` の地一色の上に、本文を `.page` で中央寄せ (最大幅1040px) |
| 罫線 | **太3px+細1pxの二重罫** (`.rule--double`) がジャーナルの署名。マストヘッドと奥付に。強い罫線は**紺** (`--navy`。デッキ「紺と躑躅」の構造色。装飾・ネスト六角形にも使うが強調には使わない)。**濃度は仕切りの大きさに比例**: 文書レベル `--rule` (紺100%) > ブロックレベル `--rule-mid` (紺60%。目次・表の天地・数値タイル) > 行レベル `--line` |
| フォント | 3役: 見出し=**しっぽり明朝** / 本文=**Noto Sans JP** / 番号・ラベル=**JetBrains Mono**。公開前に `embed_fonts.py` で**サブセット化して data URI 埋め込み** (どの環境でも同じ見た目)。未埋め込み時はシステムフォント (ヒラギノ/Noto/BIZ) にフォールバック。題字・見出しは `palt` で詰め組み |
| 見出し | 章番号は **CSS カウンタ**で自動付番 (アクセント色・大きめの等幅数字) + 末尾に罫線。目次と順序を揃える |
| アクセント | **シグネチャピンク1色** (`--accent #ff0087`)。罫・マーカー・番号などグラフィックと大きい文字は原色、**小さい文字は `--accent-deep #c2006b`** (白地4.5:1確保。ダークでは明るい `#ff77b9` に反転)。目立たせる場所を増やさない |
| リンク | **ブルー** (`--link #0087d7`) は**リンクとコード関数専用**。強調には使わない (青=参照の合図) |
| セマンティック色 | 順調=緑 / 注意=琥珀 / 危険=赤。**アクセントとは別枠**。ピルは色+形 (●▲✕○) の二重符号化 (色覚対応) |
| シンタックス色 | 新しい色相を足さない。`--kw`=濃ピンク / `--fn`=リンクブルー / `--str`=緑 / `--num`=琥珀 / `--com`=灰 (パレットの別名) |
| 数字 | `tabular-nums`。キー数値タイル (`.kv`) は明朝の大きな数字 + **上罫と同色の上・左罫** |
| テーブル | **天地の強罫+横罫のみ** (縦罫なし)。ヘッダは等幅小文字。数値列は `.num` で右揃え |
| テーマ | **既定は OS テーマ追従**。右上の丸ボタン (`.theme-toggle` ☾/☀) でライト/ダークを明示切替 (localStorage に保存・印刷時非表示)。トークンは**3状態対応** (bare `:root` / `prefers-color-scheme` guard付き / `data-theme` 属性)。印刷は常にライト配色 |

色・レイアウトの実体はすべて `assets/document.html` の `:root` トークンと CSS にある。**まずテンプレートを読むこと。**
色を触るときは「ライト / ダーク media / ダーク attr / print」の**4ブロックすべてを揃えて変える**。

## ワークフロー

1. **テンプレート `assets/document.html` を読む。** 全コンポーネントを含む動くリファレンス (BigQueryコスト最適化提案の例) を兼ねる。
2. **内容を差し替える。** 上記「前提思想」の構造に沿って:
   - マストヘッド: `.eyebrow` の文書種別 (PROPOSAL / STATUS REPORT / DECISION など)・番号・日付、`.title` (明朝の題字)、`.meta` (FROM/TO/種別/ステータスピル)
   - `.summary` → `.toc-wrap` (目次。章の `id="sec-N"` へのページ内リンク) → `.sec` の章 → `.colophon` (奥付)
   - 章番号は CSS が自動付番するので、**目次の並びと章の並びだけ揃える**
   - 提案なら比較表 (`.rec` で推奨列ハイライト) + `提案`/`依頼` callout、報告なら `.pills` (全体ステータス) + `.diff` (差分) + `リスク` callout を軸に
3. **画像は data: URI で埋め込む** (Artifact は外部URL・CDN・フォントを CSP でブロックする)。
4. **フォントを埋め込む** (公開直前の最終ステップ):
   ```sh
   uv run <skillのassets>/embed_fonts.py <対象HTML>
   ```
   - 文書で使っている文字だけにサブセットした woff2 (しっぽり明朝/Noto Sans JP/JetBrains Mono) を data URI で `<style>` に注入する (合計数百KB程度)
   - フォントは google/fonts (GitHub) から取得し `~/.cache/style-journal-fonts` にキャッシュ。サンドボックスで書けなければ `$TMPDIR` に落ちる
   - **本文を編集したら再実行** (冪等。サブセットに無い文字はフォールバック書体で混植になるため)
   - オフライン等で実行できない場合はスキップしてよい (システムフォントで読める)
5. **出力**
   - **Artifact 公開** (既定): テンプレートは doctype/html/head/body を持たない**フラグメント**なので、そのまま Artifact ツールに渡せる。**先に `artifact-design` スキルを読む** (Artifact ツールの要件)。`favicon` は文書系の絵文字 (例 `📋` `🗞️`) を渡す。
   - **ローカル HTML** で欲しい場合はファイルパスを渡す。WSL なので `file:///...` と `file://wsl.localhost/Ubuntu/...` の両方を返す。
   - レビューを集めたい資料なら `artifact-review-comments` スキルの併用を提案する (このスタイルと相性がよい)。
6. **操作確認**: 目次リンクで章に飛べるか、右上のテーマ切替ボタンでライト/ダークが切り替わり両方で読めるか。Artifact 公開後や画面確認が要る場合は Playwright で最低限の表示・操作を確認する。

## コンポーネント早見表

すべてテンプレートに実例がある。クラス名だけ抜粋:

- **マストヘッド**: `.eyebrow` (等幅の種別・番号・日付) + `.rule--double` + `.title`/`.title-sub` (明朝) + `.meta` (ステータスピルのみ。FROM/TO 等が要る資料では `.meta-item` の `.lab`/`.val` を足せる) + `.rule`
- **サマリー**: `.summary` (`.lab` + `<p>`。アクセントの左太罫 + 淡地)
- **目次**: `.toc-wrap` > `ol.toc` (番号自動・点線区切り・右端に `.dim` の補足)。テーブルと同じ**天地の強罫**で囲まれた独立ブロック
- **章**: `main.body` > `<section class="sec" id="sec-N">` + `<h2 class="head">` (番号自動付番)。小見出しは `<h3 class="subhead">`。章間は**紺の帯罫** (左からの太い帯が継ぎ目のスラッシュで割れて消えていく。紺一色) で区切られる (CSS 自動、罫線の HTML は書かない)
- **ステータスピル**: `.pill` (info青) / `.pill--ok` (●順調) / `.pill--warn` (▲注意) / `.pill--risk` (✕危険) / `.pill--mute` (○未着手)。前置きラベル付きは `.pills` > `.pill-set`
- **ラベルチップ**: `.lab-chip--fact` (事実) / `--interp` (解釈) / `--ask` (依頼)。段落の頭に置く
- **キー数値**: `.kv` > `.kv-item` (`.kv-lab` / `.kv-num` (+`<small>`単位) / `.kv-delta--bad|--good`)
- **callout**: `.callout` + `.callout-lab` (枠上に乗るラベル。提案/依頼/決定など)。危険系は `.callout--risk`
- **テーブル**: `.tbl-wrap` > `table.tbl`。数値セルは `td.num`。比較表の推奨列は `th/td` に `.rec` + `.rec-badge`
- **差分**: `ul.diff` > `.diff--add` (+) / `--del` (−) / `--keep` (＝)。右端に `.dim` で日付
- **箇条書き**: `ul.list` (六角形マーカー。ネスト可)
- **Before/After**: `.ba` > `.ba-panel` (BEFORE) + `.ba-chevrons` (`<i>`×3 のシェブロン) + `.ba-panel--after` (AFTER。アクセント枠+淡地)。パネル内 `.lab` にラベル。提案の「現状→改善後」に。モバイルでは縦積みになる
- **コード**: `.code-wrap` > `.code-cap` (ファイル名) + `pre.code`。色は `.kw`/`.fn`/`.str`/`.num`/`.com`。インラインは `<code>`
- **画像**: `figure.figure` > `<img>` + `<figcaption>` (地は両テーマとも白)
- **奥付**: `.colophon` (`.rule--double` + `.meta` の作成者・最終更新 + `table.history` の更新履歴)
- **テーマ切替**: `<button class="theme-toggle">` + 末尾の `<script>` (セットで残すこと。アイコンは JS が設定)

## 注意

- **アクセントは増やさない**。強調したい箇所が増えたら、色ではなく構造 (callout・サマリー・太字) で強調する。ブルー (`--link`) はリンクとコード関数以外に使わない
- ステータスの意味を**色だけで伝えない** (ピルの ●▲✕○ とラベルを必ず併用。テンプレートに従えば自動的に守られる)
- 見出し番号は CSS カウンタなので**手書きしない**。章の増減時は目次だけ直す
- 数値はテーブルの `.num` / `.kv-num` に載せて `tabular-nums` を効かせる。桁区切りカンマを忘れない
- 読み手が印刷する可能性が高い資料 (承認フロー用など) では、印刷プレビューでの改ページも一言確認する
- ダークテーマは自動で効く。**単一テーマに固定しない** (トークンを4ブロック揃えて維持する)
- 技術プレゼン/LT なら `style-terminal`、グラフ中心の集計可視化なら `drilldown-report` / `timeseries-report` を使う
