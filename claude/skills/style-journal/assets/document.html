BigQuery スキャンコスト最適化

パーティション分割による費用削減の提案

レビュー待ち
SUMMARY — 依頼したいこと

BigQuery のスキャン費用が3ヶ月で約2倍 (月額 ¥118k → ¥241k) になっている。 主要因は events テーブルへの全期間スキャンで、 パーティション分割 + クラスタリング (案B) により月額約 ¥120k の削減を見込む。 9月第1週の実施について、8/29 (金) までに承認をお願いしたい。

事実 増加分の 78% は analytics.events テーブルへの直接クエリが占める。 クエリ本数は横ばいで、1クエリあたりのスキャン量だけが増えている。

解釈 ダッシュボードの日次更新が全期間スキャンになっており、テーブルの成長に比例して 費用が増える構造。放置すると年末には月額 ¥400k 規模に達する見込み。

  • 調査で分かったこと
    • 上位10クエリのうち 8本が WHERE に日付条件を持つ (プルーニング可能)
    • 残り2本はレポート用の全件集計で、対象外としてよい
  • 費用の内訳と推移の詳細は 別紙ダッシュボード を参照

3つの選択肢

削減効果・工数・リスクの3軸で比較した。詳細な試算は §3 に記載。

リスク 効果が頭打ち 移行時のクエリ書き換え漏れ 固定費 ¥60k/月 が常時発生

推奨: 案B (パーティション + クラスタリング)

提案

events を event_time の日付パーティション + user_id クラスタリングで再作成し、参照側を段階的に切り替える。 並行稼働期間を2週間設け、停止時間ゼロで移行する。

根拠

  • 削減額が最大 (¥120k/月)。初期工数 5人日は約1.2ヶ月で回収できる
  • 固定費が増えない (案C は BI Engine の月額 ¥60k が常時発生する)
  • 主要クエリの 8/10 が日付条件を持つため、書き換えなしでプルーニングが効く

移行前後のイメージ

BEFORE

events へ全期間スキャン。月額 ¥241k、日次更新のたびに 1,840 GB を走査。

AFTER

日付パーティション + user_id クラスタで月額 約¥121k。日次更新の走査は 62 GB に。
