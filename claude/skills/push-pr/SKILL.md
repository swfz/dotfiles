1. すでにコミットされている変更をremoteへpushする
- コンフリクトしてしまう場合は
- fource pushはせず、既存の変更を取り込んでpushできるような状態にしてからpushする

2. Pull Requestを作成する
- PRテンプレートがある場合はそれに従った内容をBodyにする
- 必ず含めてほしいもの
    - PRの概要
    - why: 変更の背景、理由
    - how: 変更の手法
    - 確認観点 何をもってPR出してOKとしたのか
        - チェック項目
- フロントエンドや画面操作系の修正の場合は、動作確認で使ったスクリーンショットや動画をPRに添付する
    - スクショや動画はPR上に公開されるため、動作確認には基本的にダミーデータを使う(実データや個人情報、認証情報などが映り込まないようにする)
    - 変更前後で差分がわかるものは Before / After を並べる
    - 操作を伴う確認(クリック、遷移、アニメーションなど)は動画やGIFで残す
    - 動画の撮影など手元で取得が難しい場合は、スクショのみで済ませるか、ユーザーに撮影を依頼するかなど、進め方をユーザーに確認してからPRを作成する
    - 添付は `gh pr create` / `gh pr edit` の `--attach` フラグを使う(gh v2.99.0以降)
        - 本文中にローカルパスで参照しておくとアップロード後のURLに置き換えられる。参照がなければ末尾に追記される
        - `--attach './before.png#説明文'` のように `#` 以降で説明文(alt)を付けられる
        - 複数ファイルはフラグを繰り返して指定する
- すでにPRが作成されている場合は現在のコミット内容に合わせPRの内容も更新する

3. CIのチェックを走らせる

- `gh pr checks --watch`
